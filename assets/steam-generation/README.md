**状态**：可打开、可重跑、收敛；`.his` **0 errors / 0 warnings**（Control Panel 干净）

> 本案例按 `aspen-plus-automation` skill 的第一原则自建：设计输入（热负荷、蒸汽等级、给水量、循环倍率、排污、压降）先定，

> 结构上刻意复现了 `4.全流程最终版.bkp` 里"公用工程蒸汽生产"单元的手法（热源→中间载热回路→汽包产汽），但把原案例的缺陷补上：

## 2. 流程结构

```
                 E0101 吸收 600 kW 废热
   熔盐回路：  M0101 ──► P0101 ──► E0101 ──► E0102(热侧) ──► M0102 ──┬─► SALTRC(循环 0.99)
              SALTMK(补加 1%)                                        └─► SALTPG(排污 260 kg/h)
                                          │ 传热 605.09 kW
   水汽回路：  BFW ──► P0201 ──► M0201 ──► E0102(冷侧) ──► T0201 汽包 ──┬─► STEAM 925.4 kg/h
                                ▲              (25 bar, 223.99 ℃)       └─► WLIQ ──► M0202 ─┬─► WREC ──► P0202 ──► M0201
                                └───────────────────── 返液 3912.6 kg/h ─────────────────────┘   └─► BLOW 4.583 kg/h
```

两条回路**只在 `E0102` 传热耦合**（无物料耦合），因此可用同一个收敛块一次撕裂两条回路。

## 4. 物性方法（含两个必须知道的 .inp 陷阱）

| 回路 | 方法 | 说明 |
|---|---|---|
| 熔盐侧 | `IDEAL` | 硝酸盐按理想液体混合物处理；需要与 IAPWS 无关的盐物性数据时另配 |
| 水/蒸汽侧 | `STEAMNBS`（NBS/NRC 水蒸气表），逐块覆盖 | 与 IAPWS-IF97 交叉核对：饱和温度差 0.03 K、焓差 +0.08 %~+0.32 % ✅ |

**陷阱 1（2041 无法打开）**：手写 `.inp` 里使用块级 `PROPERTIES <方法>` 覆盖前，必须先在全局 `PROPERTIES` 段把该方法登记成独立选项集：

```
PROPERTIES IDEAL
    PROPERTIES PENG-ROB
    PROPERTIES STEAMNBS
...
BLOCK T0201 FLASH2
    PARAM PRES=25. DUTY=0.
    PROPERTIES STEAMNBS
```
只在块里写 `PROPERTIES STEAMNBS` 而全局没登记 → 解析失败（2041）。

**陷阱 2**：组分含 KNO3/NaNO3 这类非默认数据银行的物质时，必须显式写 `DATABANKS`/`PROP-SOURCES` 段，否则同样 2041。

**陷阱 3（循环收敛）**：手写 `.inp` 中撕裂流**不要**在 `STREAM` 段写完整规格（会与撕裂迭代冲突）；但给撕裂流一个温度/压力/流量**初值**可显著改善收敛
（本案例给 `WREC` 初值后，盐回路质量平衡由 1 % 残差变成精确闭合，且首次迭代的"泵零流量"告警消失）。

## 6. 复现 / 使用步骤

1. Aspen Plus V14 → Open `case.inp`（或直接打开 `case.apwz` / `case.bkp`）。
2. Run（F5）。`CONV-OPTIONS` 已设为 `WEGSTEIN MAXIT=300`，两条撕裂流 `SALTRC`、`WREC`。
3. 若要改为自己的工况：优先改这些**设计输入**——
   `E0101` 的 `DUTY`（可回收热）→ `T0201` 的 `PARAM PRES`（蒸汽等级）→ `BFW` 的 `MASS-FLOW`（给水量，按"产汽量/(1−排污率)"定）→
   `M0102` 的 `FRAC`（盐排污/循环比）→ `M0202` 的 `FRAC`（循环倍率与排污）。
4. 换回真实热源：把 `E0101` 的固定 `DUTY` 改成上游反应器的 **Q 型热流股**（如 `RPlug`/`RCSTR` 输出的 heat stream 接到 `E0101` 的热端口，此时 `E0101` 只给 `PRES`、不要再给 `DUTY`/`TEMP`）。
5. 换真实熔盐物性：把 KNO3/NaNO3 替换为供应商/手册给出 cp、ρ、凝固点的载热介质，重算盐流量与 ΔT（本案例隐含 cp=1.149 kJ/(kg·K)）。

## 7. 已知局限与告警

1. **本工况 `.his` = 0 error / 0 warning（已验证）**：
   说明——默认收敛容差下本案例会报 `BALMAS.1`（回路质量衡算精度 3.5E-04）。根因是**撕裂流容差偏松**，Aspen 提示语即写 "IMBALANCE MAY BE DUE TO A LARGE RECYCLE FLOW, AND A RELATIVELY LOOSE TEAR STREAM TOLERANCE"。
   解决办法（已写入 `case.inp`）：在 `CONV-OPTIONS` 中同时收紧容差并放大迭代上限——
   ```
   CONV-OPTIONS
       PARAM TEAR-VAR=NO
       WEGSTEIN MAXIT=1000
       PARAM TOL=1.E-5
   ```
   收紧后 `$OLVER01` 第 **547** 次迭代收敛，`.his` 的 error 与 warning 计数均为 0。
   （实测：`PARAM TOL=` 是有效关键字；`PARAM ERRTOL=` 或 `PARAM MAXIT=… TOL=…` 会直接 2041 无法打开。）

2. **盐物性来自 Aspen 数据银行**：本案例模型隐含 cp = 1.149 kJ/(kg·K)。正式设计必须用所选熔盐的实测 cp/ρ/凝固点替换，并重算盐流量、ΔT 与防凝裕量（冷端 250 ℃ 相对硝酸盐凝固点是否够用需按数据核对）。
3. **热源是"给定 600 kW"**：真实装置应由反应器热衡算给出；本案例刻意把它降为外部输入，以便把注意力放在产汽单元本身。
4. **换热器只到 Shortcut**：面积 12.120 m² 由 Aspen 默认 U 选项反算（U≈850 W/(m²·K)），未做几何、压降、振动、污垢等详细设计；正式设计应切 Detailed/EDR 或厂家评级。
5. **连续排污率是结果不是输入**：给定 Q 与 BFW 后，排污量由质量/能量平衡确定（0.493 %）。若水质要求指定排污率 x，则应把给水量改为 `蒸汽量/(1−x)` 再重算。
6. 盐回路为**单点补加/排污**简化模型；真实系统还有熔盐储罐、电伴热、防凝流程与排气，本案例不含。
