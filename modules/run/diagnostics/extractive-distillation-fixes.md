# 萃取精馏失败路径：先定位，再返回对应轨道

维护M15，共享P00/M01/M02/M05/M08/M09/O02；案例[C23](../../../references/principle-case-map.md#c23)。正常研究/搭建路径只在[萃取精馏专项](../../../references/extractive-distillation-workflow.md)维护，本页记录失败分派，不复制项目参数。

| 现象或失败经验 | 首要诊断与修复 | 返回与重验条件 |
|---|---|---|
| 选了NRTL/纯组分库，却没有实际二元来源 | 枚举全部可用二元源，先全选并保存回读；逐对展开命中与数值，区分缺失/default/零值 | P00；P01及当前快照准入通过后才进塔 |
| 一看到零值就自行回归为USER，或未查全来源 | 先完成逐库完整记录检索；按零值规则及原始依据处置，USER一律禁止，不能编造非零 | P00/M01/M09；记录候选为何适用或淘汰，无数据则保留未通过 |
| 只因参数非零/库名权威就采用整库 | 按每对气相框架、方程/单位、VLE/LLE、温压/组成范围与实验误差比较；一对内不得拼库 | P00；重验二元及多元预测，不继承原来的最优来源判断 |
| INP重建后数值相同，但界面来源变USER | 检查原生BKP/APWZ来源字段与展开数值；恢复适用数据库完整绑定并独立重开 | P00/M09；来源及数字均一致，不能只修显示文字 |
| 扁平COM节点名导致组分对错位 | 核多维集合坐标及CID1/CID2，输出具名普通快照；属性返回节点时正确取Value | M09；保存重开逐对/方向核实，接口成功回显不算通过 |
| 二元/三元实测区拟合很好，但富溶剂塔底温区外推 | 对照两个塔及循环包络，补高温/组成、相稳定性与焓/输送证据；宽温区标签本身不算验证 | P00；未闭合不得复算流程，也不改TUPPER伪造适用范围 |
| 换库后仍报告上一版纯度/能耗 | 在副本Reinit或明确废弃旧输出；来源/包络相关证据全部失效 | P00通过后R00重新完整运行，最终输出绑定新输入与run_id |
| 开环塔不收敛、干板或组成异常 | 先核物性准入、相数/压力、自由度、气液初值和溶剂进入的有效塔段，再核原生预设/算法 | 物性问题回P00；数值/规格问题M02/M08/M15，容差不放宽 |
| 一开始同时闭循环和全部DS，错误原因不清 | 保持设计边界，先各自开环验证萃取塔/回收塔，再闭撕裂并逐步恢复Spec/Vary | M02/M08；每次新增耦合有新日志/衡算，不能换成指定分离率 |
| 补料为负、循环溶剂“凭空稳定”或水/杂质积累 | 核组分流量与总流量的区别、库存基准、排放/损失、Calculator次序和变量所有权 | M01/M02/M08；逐组分稳态闭合，不能改写结果或静默截断负补料 |
| RR很小就称节能，或BR异常被“小分母”解释掉 | 核实际定义、V/L剖面、内循环、全溶剂负荷、两塔冷热负荷和公用工程边界 | M02/M05/M07；同产品/回收率/产能比较，说明尚未评级范围 |
| 单塔或旧输入冷重开通过，就称全厂完成 | 核当前P01、最终输入完整全流程运行、源绑定、逐组分/能量/压力闭合及最终文件独立复算 | O02；数值、物性、闭环、设备及包完整分层验收，任何必需缺口保留RUN |

通用零值规则、物性输入失效及原生来源审计以[P00](../../properties/index.md)、[P01](../../properties/check.md)和[物性来源经验](property-provenance-and-repair-gates.md)为准。原生AZEOTROPIC/Newton/初始化仅是待核验数值选项，不能修复物性证据、错误拓扑或相数。用户禁止Computer Use时不因COM困难改走GUI。

修复后按“P00（受影响时）→ 当前准入 → 单塔/闭环执行 → O01/O02”重新取证。没有可靠来源或实验数据时，记录失败、缺口与可独立完成的诊断，不通过降低验收要求或重复盲算获得PASS。
