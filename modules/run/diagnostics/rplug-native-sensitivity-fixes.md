# RPlug 原生灵敏度复做：诊断与返回运行

由 [M15](../M15-troubleshooting.md) 组织，工艺/优化判断见 [专项方法](../../../references/rplug-native-sensitivity-method.md)。这里只保留可迁移故障机制，不保存原项目数值、文件、私有路径或数据。

## 文档、存表与重跑结果不一致

分别冻结文档图表、附件旧 `SNS_TAB` 和本次运行记录。先检查活动反应集、流股边界、各床入口再热、尺寸、物性/数据库版本、容差与数据时间，再决定是否修改。设计点与曲线峰值本来就可能不同；不能通过未披露的参数调整“对齐截图”。证据不足时明确是哪两套来源不一致，保留原样复现及待核依据，返回 M03/M14。

<a id="version"></a>
## 可打开但组分输入不完整

较新版本的档案可能能被旧版本界面读入，但指向本机不存在的数据库。以 `NextIncomplete`、组分身份及可用数据库确认根因，而非只改档案版本号或认为打开成功即兼容。

需要兼容转换时，在副本内映射到实际安装的库；不做未经检查的全局文本替换，不把缓存参数来源标签当作可以随意替换的数据库入口。记录转换前后库、参数保留/重查方式、组分身份与结果差异，再运行/冷重开。组件识别完整只证明该输入问题已解决，不能证明两代物性等价或已有实验验证。联动 M01/M09。

## 改名后出现空的旧 Sensitivity，翻译报缺 Tabulate/Vary

编辑文本备份中一个分析名称，旧结果 DSET 或其他保留记录可能仍引用旧名，加载后恢复成空对象。先导出当前输入并枚举实际分析列表，确认额外对象和缺少句子的对象身份。优先通过 Aspen 对象接口修改/移除确实废弃的对象；文本修改时需同步相关引用或稳定保留原名。Reinit 不等于删除多余输入对象。

重新回读活动列表、Define/Vary/Tabulate 和输入完整性，再运行并检查新日志。不能只在报告里忽略空对象，或为了无报错禁用用户要求的分析。联动 M09。

## 档案文本导入后定义缺失

不要按普通长行文本任意拼接备份记录。已验证过的 V14 导入路径需要遵守原记录的分隔、换行与句法；过长记录可能造成定义没有按预期载入。`.bkp` 与 `.inp` 的续行方式不同，不可混用。

优先使用已核 COM/MCP 节点修改；必须生成文本时按本机已核格式换行，随后导出规范输入，检查分析对象数量、每个变量与表达式。`NextIncomplete` 返回完整仍不能替代新运行中的输入翻译检查。联动 M09。

<a id="history"></a>
## Run2 返回后历史还未完整保存，或重开归档后找不到日志

- 运行记录可能位于归档打开时创建的嵌套工作目录；在本次隔离目录内递归定位，与本次 run_id 和时间绑定，不能拿邻近目录旧历史代替。
- 有的历史尾部在结果导出/保存后才完整写出。若只有部分结果生成记录，先确认求解已结束，再通过已核导出/保存并短时有界检查完整结尾或错误汇总；超时仍标未验证，不无限等待或直接报零错误。
- 若本机关闭会删除运行临时文件，在关闭所拥有会话前留存已完整落盘的历史。保留实际取证路径与 run_id，避免复制到验证目录后混淆原始出处。
- `PER_ERROR` 不是跨所有状态节点通用的错误计数。读取消息正文和完整严重级别；纯 INFORMATION 不冒称 Error，也不能因为字段名可疑就忽略真正警告。常规积分误差估计文字不等同于 Aspen ERROR，但未知消息仍需分类。

按 [历史核验](run-verification-and-reconcile.md) 和 [O02](../../output/check.md) 再检查，失败回 M09/M08，不用“Run2 正常返回”代替实际完成证据。

## 容器数值、结果单位或归档结构造成假失败

流股结果容器 `Value` 可能是表标记，应读取实际子流股/组分叶节点并核 `UnitString`。结果单位或短列标签与输入不同，按真实列头映射比较，不按文件名或列序号猜。

本机 Aspen 生成的部分 `.apwz` 是包含 `.apw`、`.appdf`、`.bkp.backup` 等成员的归档。只检查成员名必须以 `.bkp` 结尾会误报损坏；不应为迎合自写检查器而改写 Aspen 原生结构。以真实格式检查、Aspen 独立打开和重新执行验证为准，ZIP 校验仅证明包结构。

## 原生数值可复现但工程结论仍不成立

单位来源不清、整个床层超动力学范围、几何变化却固定压降/装填假设、Heater 无压缩功地指定更高压力、热量边界漏进料制备，均需回对应工艺模块。若峰顶近邻差异小于合理数值精度，回 M08/M14 做有依据的细化/收紧容差或降低报告精度。

修复后必须再走 RUN → OUTPUT → CHECK；不能把保留了模型、生成了图、逐位复现或哈希一致当作工程最优已验证。来源缺失且无法独立修复时，只按已完成的复现/诊断范围交付，并明确阻碍，不擅自更换用户目标或参数。
