# P00 物性前置轨道：输入 → 检查 → 流程准入

接收 [I01任务判断](../intake.md) 的任务范围，在 [R00流程模拟](../run/index.md) 之前独立运行。M01提供工程原理，M09负责原生录入/回读，M15协助排错；这些支持调用不代表已开始流程模拟。物性输入不再埋在流程搭建中，P01也不再是输出模块末尾的补查。

<a id="method-selection-and-binary-gate"></a>

## 全局方法选型与二元参数准入

普通流程搭建、物料热量衡算及数值复算，按当前相态、压力、组成和主要分离机理，选择一套有依据、可用且最适合当前工况的全局物性方法。记录选型理由和适用范围，优先引用能支持该方法选择的文献。常规模拟允许使用与文献参数不同的适用 Aspen 原生数据，文献对方法或相行为的支持即可作为选型依据之一。只有明确要求复现指定研究时，才按复现范围核查文献参数与结果的对应关系。只有现用方法与工况存在冲突、关键结论对方法敏感，或用户要求比较时，才补做针对性的替代方法对照。对普通流程核算，无需把多套方法比选或全工况实测复现作为先决条件。涉及必要的局部物性时，明确该模块的方法和接口。

完整性检查覆盖**该方法和实际工况需要的输入**，包括纯组分、二元参数及适用的 Henry 或电解质输入。范围以模型实际调用的相关式、相态和工况为准。优先保留来源明确、适用、完整且已生效的原生记录。有缺参、无依据零值、单位或方向错误、气相框架或相平衡用途不符时，优先查适用原生替代。若现用方法的必需输入难以补齐，而另一适用方法拥有完整的原生输入，重新选型并复核关键相行为后继续建模。结果中分别标明物性输入准入、当前用途的适用性和独立实测验证范围。用户要求实验或工业复现时，按其范围补证。关键相行为仍不明确时，做能决定本次分离结论的针对性核对。

## 前置顺序

1. **冻结边界。** 确认组分真实身份、相态、温度/压力/组成包络、所需平衡与焓/输送性质、气相模型、局部方法和用户禁止项。先从任务与工程依据提出包络，不能先运行未经核验的流程再用其结果证明物性适用。
2. **盘点并启用来源。** 对需要的二元参数，从当前安装枚举全部可用数据源；先全部启用并保存回读，随后才逐组分对查参数和换源。可用、已启用、查找顺序、实际命中四者分别记录。纯组分库不等于二元参数库；全选也不意味着全部适用。
3. **逐对查零与缺项。** 展开实际必需记录及方向、字段、数值、单位、范围与来源。null、缺失、默认回退和0分别登记。必需交互字段出现无依据的0时，先追溯并比较适用的完整替代记录。已有物理和原始记录依据的零值按现行验收要求判断。确有模型定义和原始记录证明固定0的项单列；用户当前不接受的零项仍为未通过。无可靠替代不手改非零、不零填缺项、不拼系数。
4. **核二元记录是否适用。** 当前实际命中的完整记录符合模型、气相框架、相平衡用途及关键工况时直接保留。确有问题或存在影响关键结论的候选差异时，比较完整来源、方程、范围及可用实验依据。不同组分对可有据选择不同来源，换源后对受影响的多组分预测复核。非零或库名不能单独证明适用。
5. **原生输入与保存重开。** 物性输入一律禁止USER，仅允许适用原生数据库绑定；禁止手工覆盖和自行回归写入，找不到合适来源就保留未通过。库内原始拟合记录属于原生数据库记录，不等于自行拟合后录为USER。核原生APWZ/BKP的来源和实际系数。导出INP可能只保留展开数值，重新导入会变成USER；不能以数值相同代替来源绑定。新COM会话独立重开后再核方法、全源选择、逐对来源、系数、单位、范围。
6. **按任务核物性适用性。** 常规流程用方法适用依据和必要工况的相态、关键分离趋势核对。遇到共沸、液液分相、稀溶气体或决定关键结论的外推时，针对对应相态、组分和温压补算或对照证据。精馏按[相图前置分析](../../references/phase-diagram-before-distillation.md)核关键分离边界。实验精度或工业验证按任务要求另列；已有适用性的模型近似可以用于约定范围的流程计算，独立实测结论只覆盖实际验证工况。
7. **P01检查与流程准入。** 调用 [P01](check.md) 和 `check_delivery.py`；五项必需检查全部PASS才得到CONTINUE。生成下述交接包，再用 [check_process_gate.py](../../scripts/check_process_gate.py) 核当前快照后进入R00。FAIL/UNVERIFIED留在本轨道修复，不先搭完/跑完流程再补查。

<a id="component-order-and-bip"></a>

## 组分录入顺序与二元参数检查

- **Aspen 的组分输入按常压沸点升序。** 对具有正常沸点的常规组分统一使用 101.325 kPa 下的值，同一组分表标明 Aspen ID、中文名和温度单位。若物料清单或 Word 在交付范围，表内顺序与 Aspen 实际输入一致。无正常沸点的组分用升华、分解或其他适用状态标注，并与常规沸点区别记录。离子、固体、伪组分等如受原生组分类别或依赖顺序约束，保留其合法类别和顺序并注明。用户指定其他压力或排序规则时以当前约定为准。
- **先定方法和相态，再定所需二元表。** 按相态、压力、液相非理想性、离子或稀溶气体选择可验证的模型。回读全局方法、模块局部方法、气相模型、二元记录的来源名和版本。NRTL-RK 之类是物性方法，VLE-RK 等可出现在参数来源名里。选中方法或来源列表只证明设置动作，具体参数是否生效须逐对回读。
- **逐对追溯 BIP 完整性。** 先列当前工况所需的二元组分对和相关表，包括适用的活度系数、EOS、Henry 或电解质参数。用 BIP 完整性检查找缺项，并核实际命中的组分身份、i/j 方向、有效字段、温度方程、单位和数据温区。按方程核对整组记录。NRTL 表中 AIJ、AJI、BIJ、BJI、CIJ 等字段随数据形式适用，列位置不代表必须全部非零。组分排序后按组分 ID、方向及原生记录重新校对来源和系数，不按原表行号复制。
- **按用途验多组分结果。** 精馏核 VLE、相对挥发度及共沸，澄清与萃取核 LLE 和两相组成，可能有气液液时核 VLLE 与相稳定性。吸收按需核 Henry 的气体、溶剂、温区及系数约定。证据相同范围内的相平衡、误差及物性覆盖优先于零项数量。缺参只在用户授权的原生估算范围内处理，最终按 P01 区分数据库、估算、缺项与实测未验证。

<a id="binary-input-decisions"></a>

## 二元输入何时算完成

| Aspen 实际回读 | 决定 |
|---|---|
| 必需组分对已有完整、适用、来源明确的原生记录，方向、数值、单位与有效范围均符合当前要求 | 保留并使用。自动匹配和手动选择均可，判据是实际生效的组分对记录及其字段。记录有依据的固定零、拟合零或本方程未使用项 |
| 二元数据库已启用，但某必需对为空、默认回退、来源不明或只有无依据的零值 | 该对尚未录入完整。打开 BIP 完整性和实际来源表核对，刷新检索并查看当前安装内适用的原生记录。只勾选数据库或成功写入设置不能证明已命中 |
| 已绑定来源，但关键记录缺字段，或方程、方向、温度单位、气相框架及适用相不匹配 | 优先从适用原生来源中更换该组分对的整条记录，并重新回读和核受影响相行为。单元局部物性也应在实际生效的表内取证 |
| 当前来源合适，只是另一个库非零项更多，或字段按方程有依据地为零 | 保留当前记录。用户另有明确零值要求时，按其验收条件判断并说明依据 |
| 查不到适用完整的原生记录，任务允许使用 Aspen 原生 UNIFAC 估算，且该估算对当前组分和方法可用。界面显示为 UN 时先核对实际估算选项 | 只估算仍缺的必需对。保存并回读具体对、实际字段、估算身份、开关及使用范围。按下节在授权范围内试算，估算与数据库来源、实测验证分别列示 |
| 查不到适用记录，也无获准且可用的原生估算 | 把该必需对和受影响工段列为未通过。禁止 USER、手填、拆借不同记录的系数或把缺参当成零 |
| 当前方法及本工况确实不需要该组分对或某一字段 | 写明物性模型或有效相、组成范围的依据。无需录入占位数据；后续新增组分、局部方法或相态时重核 |

普通数据库路线的输入完成条件为：**所选方法的实际必需输入均有适用、来源明确的完整记录，满足用户的输入要求，并在原生 APWZ/BKP 保存后独立重开读回一致。** 已明确授权的估算路线单列为“估算已录入、可在授权范围试算”。没有要求时不强制手动重选已有适用记录，也不为比较非零个数反复换源。输入状态与实测验证状态分别报告。

## 用户明确允许原生估算时的搭建与数值联算

若用户已授权用原生估算补齐缺项并继续搭建及联算，按以下输入状态放行获准的数值工作。此路径在工作副本上执行，可覆盖独立工段和整厂，保留P01原结论及待核物性。无需等待工程物性全项通过，也无需重复询问已授权范围。

1. 先枚举并启用每张相关二元表的全部可用来源，保存并读回。逐表核对实际命中，优先绑定适用的数据库完整记录。不合适的换源，界面或接口缓存过期时重新选择并读回，核对实际值和来源。检查范围覆盖实际使用的二元参数表。
2. 剩余的NRTL缺项按用户指定用NRTL二元表内的原生估算，如UNIFAC，逐对记录估算来源、字段及覆盖温度。纯组分确有缺项且用户允许时，单独用PCES和有出处的结构、已知常数补齐。表内估算和全局Estimation分别记录。全局开关按用户指定的最终状态读回，要求关闭时核对ALLONLY=NONE和各全局估算请求为NO。若用户还要求停止表内自动估算，另读回表内开关和已生成记录是否保留。不得借估算路径录入USER系数或把估算标成实验数据库记录。
3. 对溶解气体按方法、溶剂和组成范围判断是否启用Henry，回读实际组别、局部方法、系数及来源。更换方法或引入酸液、离子或新相时，重查相关边界。纯组分饱和曲线只能核对纯组分；用含真实杂质的混合物数据判断杂质分配。Aspen随附电解质样例可参考化学体系和反应定义，先识别其显式覆盖值，再决定哪些记录可在数据库中重新绑定。
4. 保存原生副本并独立重开，记录授权原文、输入哈希、来源和估算清单、实际开关、适用范围缺口及数值运行范围。核实指定输入已生效且获准试算所需字段齐全后，即可用获准的原生执行接口逐段搭建、实算、验收数值接口并接入。读新日志，区分已知物性问题、单元问题和撕裂不闭合，逐项保留。此路径不修改正式准入脚本或报告，也不将试算结果标成工程验收或正式交付。无明确授权仍走原正式准入。

## 交接包与失效

交接包包含物性阶段合同、候选证据、P01报告、原生文件及来源/范围审计、`property_snapshot`、当前独立回读快照和准入报告。快照必须覆盖组分、全局/局部方法、全部已启用二元来源与命中记录、参数/单位/温度形式、适用相、T/P/组成包络及零值约束与USER禁用审计。用真实回读生成，不复制旧快照冒充当前设置。

快照用JSON对象，至少含非空 `components`、`methods`、`scope`、`parameters` 数组及 `source_inventory`。每个parameters记录须有 `source_type="database"` 和回读的 `source`；逐字段来源可附 `field_sources`，不得含USER或原生用户值标记。source_inventory须含整数 `user_parameter_count=0`、`unresolved_source_count=0`，来自对当前模型全部物性输入/覆盖的审计；不能只统计有利记录、隐藏USER。后者须有布尔值 `binary_parameters_required`；为true时同时记录 `available`、`enabled` 来源名称数组，准入脚本核全源已启用且参数记录非空。无二元参数需求时显式记false及 `reason`，不伪造组分对；parameters仍可记录所需纯组分等参数。阶段候选中的 `property_snapshot={path,sha256}` 必须同时作为五项P01检查的证据，绑定实际阶段输入与迭代。每次流程运行前重新导出当前物性快照，用准入脚本比较，不以全流程文件hash变化为由重贴旧证据标签。

```powershell
python "<skill>/scripts/check_process_gate.py" --request "work/process-gate-request.json" --report "work/process-gate.json"
```

请求字段：`property_contract`、`property_candidate`、`current_property_snapshot`（均为真实文件路径）。准入脚本重验P01合同与证据，检查冻结/当前快照内容一致；只有 `PROCESS_READY`（退出码0）允许开始依赖性流程计算，其余返回 `PROPERTIES`（退出码2）。它不执行Aspen，也不自动证明工程语义。

旧模型的文件/日志取证可先做；真正复算仍须本轨道证据有效。纯读取/导出且不运行、不修改物性的任务可由I01记录 `READ_ONLY` 辅助路线，经M09到O01/O02，不能借此放行流程计算。

改变组分、来源、系数、方法、相数或温压/组成范围，立即退回P00并使受影响流程结果失效；保留原件，在副本清除/明确废弃旧结果。新流程结果超出已批准包络也退回本轨道，不仅检查数值收敛。数值性修复不改物性时可留在R00，但每次执行前仍核当前准入。

经验及原理见 [M01](../run/M01-properties-and-boundaries.md)、[M09](../run/M09-execution-interfaces.md)、[换源与输入失效案例](../run/diagnostics/property-provenance-and-repair-gates.md)。具体某库在某体系表现好，不能沉淀为所有体系的默认库。

萃取精馏另读[专项第2–4节](../../references/extractive-distillation-workflow.md)：研究三个二元及多元数据、富溶剂高温包络、逐体系择源、原生来源与展开系数双重核查；P01未过不进入任一依赖单塔。

**USER拒绝条件：** 参数来源为USER（含大小写/空白变体）、手工/自行回归来源、数据库名下夹入USER字段、原生用户值标记、来源缺失或全模型USER/未知来源计数非零/未审计，都不得进入流程。现有模型可只读取证；禁止改变标签、重新包装自填库或缩小审计范围绕过。纯组分等非二元输入同样适用。
