# O02 输出内的检查子模块

这是[O01输出模块](index.md)内部的必经检查，不是交付后的提醒。接收I01冻结的要求、R00本轮输入/运行证据和O01当前候选文件；检查结果决定交付或返回运行。

## 检查矩阵

| 检查 | 按什么判断 | 失败后返回 |
|---|---|---|
| 用户要求逐项兑现 | 每个requirement_id对应实际结果/文件/格式、阈值与证据；禁止漏项、替换用户指定值/拓扑或把部分闭合当完整流程 | 负责该要求的M模块；原因不明先M15 |
| 文件与身份 | 原件保护、候选哈希、最终输入与run_id、外部依赖、来源绑定、实际对象/禁用状态一致 | M09+M15 |
| 输入完整和执行 | 本机核验的NextIncomplete、活动块/循环/DS状态、真实新日志；Run2返回不等于实际执行或通过 | M09/M08+M15及实际设备 |
| 错误与警告 | 当前完整历史和Control Panel零Severe/Error/Warning；解析失败/日志缺失不是零；临时迭代故障也需诊断后重跑验证 | M15再联动根因模块 |
| 求解与规格诚信 | 原/新实际容差、残差定义/缩放、Spec/Vary/目标、模块身份；不得放宽容差、伪造结果或用指定分离替代真实预测 | M08+M15及实际工艺 |
| 物性和相数 | 必需参数来源/方程/方向/单位/范围、VLE/LLE/VLLE和相稳定性、焓/输送性质；修复后验证受影响边界 | M01及M02/M03/M05/M11/M12+M15 |
| 衡算与物理可行 | 独立总量/组分或元素/电荷、能量、压力和温位；明确基准/单位及误差，不能只读软件成功标志 | 相关M模块+M15 |
| 独立复现 | 从冻结候选复制到新目录/新COM复算，设置、关键结果和日志一致；明示初值不能称无初值稳定 | M09/M08及相关模块 |
| 设备与可操作性 | 用户要求范围内的水力/面积/温敏/传递/热点/NPSH及评级证据；初筛不当厂家评级 | M07及M02/M03/M04/M05/M13 |
| 图形可见/可编辑 | 用户最新PFD、真实端口/连线、不重叠、标签及要求的图/数据；XML/Plot对象存在不等于显示通过 | M09及相关工艺 |
| 包与说明一致 | 文件能打开、格式真实、报告/图表同工况、清单/哈希、来源/假设/外推和未验证项准确 | M09+O01，仍经R00返回 |

按用户任务预先确定required_checks；不适用项必须有理由，不能因失败改为不适用。纯读取/解释任务不必假造一次Aspen运行；要求真实模型交付的运行/日志/复算不可省略。

真实模型交付的基线必需项包括用户要求、文件身份/原件保护、输入完整及活动对象执行、当前历史与Control Panel、实际容差/规格、物性适用性、独立衡算和冷重开；用户要求的图形/设备能力再增加对应项。不能只登记一个“无报错”项目就把整体验收称为完成。只读或明确限定范围的任务应在I01写清范围，O02不得扩大结论。

## 原理和案例

原理读[M01守恒与物性](../../references/textbook-properties-and-boundaries.md)、[M08-K07/M09-K01](../../references/textbook-numerics-economics-and-custom-models.md)及[诚信边界](../../references/convergence-separation-and-energy-integrity.md)。工艺检查按[详细条目](process-acceptance.md)。案例借鉴[C06/C08/C10/C12](../../references/principle-case-map.md)的隐藏故障、初始化保存与文件一致性经验，不因这些案例存在就认定本次通过。日志、Reconcile和报告单位细节共享[M15正文](../run/diagnostics/run-verification-and-reconcile.md)，检查发现问题才进入修复。

## 状态和回流合同

每项采用 `PASS / FAIL / UNVERIFIED / NOT_APPLICABLE`，保留结论对象、预期、实际值、证据路径/哈希、input_hash/run_id、检查方法及责任模块。缺证据、格式不识别、旧日志或口径不可比较都为未验证，不能默认通过。需要自动核对时按[结构化记录格式](evidence-format.md)保存冻结合同、当前候选及证据；合同改变会使原检查身份失效。

任一必需项FAIL或UNVERIFIED → 生成 `issue_id、requirement_id/check_id、现象、预期/实际、证据、失效接口、owner_modules、重验条件` → 返回[R00](../run/index.md)。出错/原因未定时包含[M15](../run/M15-troubleshooting.md)。R00修复后重新运行和输出，本检查重验受影响项并核对全部必需项仍有效；不能沿用修复前失效的通过结论。

全部必需项PASS或有据NOT_APPLICABLE，且无未闭合问题 → `DELIVER`。文件/日志预检查通过只证明其覆盖范围，不能自动提高物性/工业有效性等级。辅助脚本[check_delivery.py](../../scripts/check_delivery.py)只核对任务合同、证据身份/文件和可识别日志，工程语义仍须独立检查后如实登记。

## 回查前置检查

按I01登记适用的[P01物性检查](properties-validation.md)和[K01动力学检查](kinetics-validation.md)，核其CONTINUE报告及与当前有效设置/范围一致的子快照。最终EARLY-* review项必须有新生成的有效性审计，保留原始阶段run_id/input_sha256及报告哈希，不给旧报告换标签。关联参数或条件改变必须重查；无关对象导致整文件hash变化时，也应以实际子快照比较确认其仍适用。

全部检查在同一会话执行；使用原始反馈、独立衡算与冷重开取证，不需要另一agent、身份声明、verdict.json或私有记忆接口。检查工具为check_delivery.py。
