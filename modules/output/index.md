# O01 输出模块

## 输入与候选交付

只接收[R00运行模块](../run/index.md)的候选结果，不把任何一个子模块的完成当作最终完成。冻结 task_id、iteration_id、run_id、最终输入/设置、文件哈希、原理/案例来源、实际结果及未解决项。

逐项对照[I01](../intake.md)记录的用户交付清单requirements：文件类型/名称/位置、可编辑性、流程/拓扑、产品/回收/能耗指标、物性/参数来源、要求的相图/图表、用户最新PFD、复算、说明与适用范围。数字、图表、模型、报告需绑定同一最终输入和运行，不用旧图/旧结果拼成新交付。

文件仍是候选，必须调用本模块内[O02检查子模块](check.md)。检查通过才发布为最终交付并给出可点击文件链接；问题未闭合不能标“完整通过”。

## 输出组织

候选包至少包含用户要求的原生/可编辑文件、参数与来源、实际运行/独立验证证据、结果与需求对照、未验证/外推范围。按任务裁剪，不为只读解释任务凭空增加模型/经济优化/厂家评级要求。

验证时从候选/交付文件复制到独立工作目录；不得在交付目录InitFromFile2，保证交付字节不被初始化改写。原件、候选、测试副本和最终交付分别管理；只在当前最终候选上生成报告、图表、清单与哈希。

## 检查结果分流

- O02全部必需项通过 → `DELIVER`：最终交付及已验证范围。
- O02出现报错、不符用户要求、证据缺失/陈旧或文件不一致 → 返回 `RUN`：带issue清单进入R00，按根因调用M15及相关工艺模块；修复后新输出、新检查。
- 真正无法独立解决的外部数据/许可/权限或物理不可行 → 保留失败/未验证及具体依据，报告尚未达成的用户要求，不能删除要求或改验收门槛。尽可能先完成其他可独立处理工作。
