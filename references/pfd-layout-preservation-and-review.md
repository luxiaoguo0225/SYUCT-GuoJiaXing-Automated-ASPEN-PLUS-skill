# Aspen PFD：保留用户布局、解析与验收

来源：2026-10-01 PDO 排版任务。本次用户手工参考可学习，后续自动“默认标签/正交布线”结果被用户明确否定。本文记录方法、限制及失败原因候选，不宣称已找到获认可的自动布局算法。

## 1. 先确定编辑基线与用户限制

本次用户要求：

1. 模块标签和物流信息标签只要不明显遮挡其他信息就保持默认，不得随意调整。
2. 物流尽量水平/竖直，必要时弯折；同一设备多股进料/出料的源头和结尾不能重叠。
3. 允许各方向翻转模块。
4. 禁止 Computer Use；允许联网寻找算法辅助。
5. 最后要求记住用户手工案例，停止继续改图。

这些是该用户/任务的要求，不能无条件作为所有用户的偏好。任务中的禁止工具约束优先于 skill 推荐；不要用其他 UI 接口绕过禁止。用户反馈不满意时，不能把“无斜线/无错日志”作为排版已完成的依据。

编辑始终以用户最新文件为基线。已有布局是待理解的设计信息，不能先丢弃图形重排。保存原始副本和哈希，分别记录位置、方向、管口、标签、锚点和流线路径变更；优先局部调整。

## 3. “默认标签”不能只用一组坐标定义

- 原生标签依赖图标、比例、朝向、路径、锚点及 Aspen 版本；`Label At 0 0` 不是通用默认。
- 本例参考图中模块标签统一偏移源自先前生成文件，不能因此把它称为出厂默认。用户的手工位置与其默认标签要求应结合实际图面理解。
- 不得以旧自动捕获文件里的 Label At 覆盖所有用户标签。先保留原位置，仅在实际遮挡时局部移动并记录原因。
- 物流 `At` 是图形锚点；即使 Label At 不变，移动 At 也会移动物流信息。全局重置锚点仍可能违反“不随便调整标签”。
- 热流与物料流的 GLOBAL/TYPE 显示配置不同。别把热流按物料流渲染出虚假的 T/P 信息；数据框字段须以实际显示配置为准。

## 4. 按管口对齐，不能只对齐模块中心

同一行模块中心一致不保证物流水平。先依据图标、比例和朝向确定真实连接点，再选择模块中心位置。转动/翻转后重新计算管口和标签。

本例 RPlug ICON 1 的管口相对中心约为入口 (−0.525,−0.375)、出口 (+0.525,+0.375)。用户将 OX-R1、HEAT-OX、OX-R2 的中心高度设为约 0.373879、0.749612、1.123879，意图是主物流接近同一管口高度。强制同中心高度会引入台阶和弯折。此偏移仅是本例图标实测，不可套所有 RPlug。

多流股连接不能仅检查端点间距：还需检查相邻端点、源头/结尾引出段、共线重叠长度、折弯次序，以及是否看起来仍连在真实图标边界。`$ D` 改变图形端接位移，不是新增物理管口。

## 5. BKP 与 PFS 的安全边界

- BKP 图形段从 `GRAPHICS_BACKUP` 开始，通常止于 `$_SUMMARY_FILE`；某些未运行的保存文件没有 SUMMARY，后边界为 `$_ADS_FILE`。按实际标记识别，缺失时停止修改，不猜边界。
- 修改图形时保留段前、段后原始字节；保留未知记录、对象和配置。latin1 可作逐字节映射，不能用会损失字节的解码或替换错误策略。
- `.inp` 图形尾部常从 `;PFS V 5.00` 开始，格式不能等同 BKP。工艺 FLOWSHEET 与图形 ROUTE 是不同的数据层。
- CRLF/LF 保持一致，防止重复转换形成 `\r\r\n`；手写输入物理行换行使用 Aspen 的 `&` 续行语法。
- PFS 对象头计数不等于模块数加流股数。本例头部 116，但解析到 44 个模块、71 条流股；剩余计数原因没有确定，不能硬改成 115，也不能宣称 72 条流股。

## 6. 路由记录的已见格式

```text
BLOCK
ID: OX-R1
ICON: "..."
At 7.0 0.373879
Label At -1.0 -1.65
Scale 1.0 Modifier 0

STREAM
ID: ...
GLOBAL 117
TYPE 0 TERMINAL 0
At ...
Label At ...
ROUTE 0 0
r r ... ... 0
x x ... ... 0
y 0 ... ... 0
t l ... ... 0
$ D ... ...
ROUTE 1 0
...
```

也存在 `y x` 等组合。坐标行的第二个代码可能是数字 `0`；只用 `[rxytlud]+` 识别两个代码会漏点，导致错误端点和路径判断。需支持科学计数法，保存原始代码，不通过字母含义猜位置。

- ROUTE 0 / 1 在本例分别从锚点回源头、从锚点到终点；可能存在不同页号的多组 ROUTE/At 记录。不要仅处理第一页后悄悄丢弃其他页。
- 外部进料/产品可能只有半条路径；空的另一半及 TERMINAL 状态必须保留。错误地统一中点锚点可能截掉外部流股的一段。
- `$ D` 记录终端附加位移。本例生成器以“存储 t 点减位移”反算原连接点，不能再把同一位移重复加到 t 点。审核保留两者及其关系；其他图标/版本仍需原生显示验证。
- 坐标记录须按原顺序处理。同一 ROUTE 下的重复点可用于结构表达，不应未经确认删去。
- 图标 Modifier 的编码需本机验证；不假设 0/1/2/3 分别是什么翻转。
- BKP 的工艺连接包含 `BLOCK BLKID="..." IN=(stream M0-1 ...) OUT=(...)`，可能跨行、带引号。物料与热流分组以工艺连接为准，不靠离哪个模块近来猜流向。

## 7. 算法可以辅助，不能替代图面验收

曾参考原始论文 [Orthogonal Connector Routing](https://people.eng.unimelb.edu.au/pstuckey/papers/gd09.pdf) 和 ELK/libavoid 的 [共享端路径惩罚](https://eclipse.dev/elk/reference/options/org-eclipse-elk-alg-libavoid-penaliseOrthogonalSharedPathsAtConnEnds.html)、[算法说明](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-alg-libavoid.html)。本次实现是借鉴思路的自写网格 A*，没有实际调用 libavoid，不能声称采用其全部能力或保证最优。

试验包括压缩网格、标签障碍、共边惩罚、端口引出段与间距检查。虽得到无斜线、源尾局部无共线重叠的几何统计，用户仍不满意。以下只能作为改进方向：

1. 以现有布局路径为候选，只修改实际冲突区域。保持主干、长距离回路走廊、工段关系和用户微调。
2. 优先实际管口对齐、不同流股独立引出，再考虑绕障碍；模块方向可以按用户许可优化。
3. 多目标同时考虑弯折数、长度、交叉、共享段、标签距离、模块边界、信息可读性和对原图的改动量；不只优化“零斜线”。
4. 未知文字框尺寸不能当精确硬障碍。夸大估算框曾造成过长锯齿回路；仅用估算图不能保证不遮挡。
5. 长路径的外侧走廊应按实际长线段识别，不能用所有点的最小 x 当整条回路走廊。曾导致 QOX2 多次绕远。
6. 强制坐标舍入会造成微小台阶；如采用容差需报告容差和图形单位，不虚称全部精确水平/竖直。
7. 首尾固定短引出段仍可能在较远位置共边，应检查一定长度范围并检查全路径。本例的 0.75、2、0.22 等图形阈值是试验参数，不能说是 Aspen 原生端口标准。

## 8. 分层验收与失败状态

| 层级 | 应检查 | 不能推出的结论 |
|---|---|---|
| 文件完整 | 标记、可解析对象、未知记录、哈希、段外字节 | 能被 Aspen 正确显示 |
| 工艺不变 | 拓扑、规格、物性、反应、导出模型输入 | 图面整齐 |
| 几何 | 斜线、端点距、共享段、锚点、可疑绕路 | 标签无遮挡、用户满意 |
| Aspen 运行 | 独立冷启动、模块、日志、衡算 | 图面美观 |
| 原生图面 | 实际图标、字体、数据框、连接与全图可读性 | 用户必然接受 |
| 用户反馈 | 最新参考及明确评价 | 工程参数得到重新认可 |

Computer Use 被禁止且没有真实截图时，报告应写“文件/坐标/COM 验证；原生视觉未复核”。Matplotlib 示意图只是近似图，不冒充原生截图。用户已拒绝的版本即使冷启动成功也应标为“排版未通过”，不能作为最终排版成功经验。

## 9. 只读检查工具

`scripts/audit_pfd_layout.py` 支持 BKP 或本 skill 的 PFS 文本，输出对象、全部可识别路径、锚点/标签、可疑斜线、同设备端点距离，以及两个图形版本的字段变化。仅使用 Python 标准库，不启动 Aspen、不改文件、不证明视觉合格。

```powershell
python scripts/audit_pfd_layout.py assets/pfd-layout/pdo-user-adjusted.pfs.txt --output audit.json
python scripts/audit_pfd_layout.py original.bkp --compare candidate.bkp --output comparison.json
```

默认阈值是检查参数，单位为 PFS 图形坐标。工艺连接仅对已见的编码 BKP 形式提取；不支持的连接、重复 ID/多页和未知记录均需显式报告，不能静默给出“全部检查通过”。最终使用独立工艺导出比较与原生图面复核补足工具范围。
