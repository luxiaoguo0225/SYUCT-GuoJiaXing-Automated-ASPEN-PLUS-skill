# 物性溯源、文件范围与流程修复的核验关口

本文沉淀通用判断，不包含项目数值、拟合结果、设备身份、专属拓扑或模型资产。接口行为必须在当前安装版本和工作副本中核验；这些方法不能代替物性或设备适用性证明。

<a id="m01"></a>
## M01 数据来源与零系数

- **全局组分库与二元参数库是不同层次。** 选择纯组分数据库，不证明各物性方法下的二元参数已经找到。逐项核对实际所用方法、必需组分对、搜索顺序、选中来源及最终生效记录；界面显示可用数据库也不等于已选用。
- **先分辨零的含义，再决定换库。** 源记录明确给出的零值、高阶温度项的省略，与查无记录后使用的默认值不同。对无来源或不适用的零值，检索其他适用数据库并检查其记录；有依据的零系数保留。不得以“每格都非零”为完整性标准，也不得为了消除零而拼凑不同相关式的系数。
- **参数审计以必需记录为单位。** 记录组分方向、来源与版本、方程形式、单位、温度范围和适用相。Henry 参数要核对溶质到溶剂的方向及每个相关溶剂的覆盖；部分溶剂有数据并不证明混合溶剂处理完整。无需给实际方法不使用的所有组分对强行填参。
- **数值与来源绑定分别检查。** 输入文本可能只保留已解析系数，重新导入后显示为 USER；系数相同不能证明原生文件保留数据库绑定。对最终交付的原生文件独立回读数值和来源。文献回归或用户输入如实标为相应来源，不能伪装成内置数据库记录。
- **更换来源是模型变更。** 比较前后相平衡、溶解量及受影响的循环、产品和热负荷，在相同约束下复算。没有报错不能证明参数覆盖完整；逐项列出缺失、估算和超温外推，不能笼统声称“全部物性已验证”。
- **缺库后的回归要与所选热力学约定一致。** 核验原始实验来源、组分方向、压力和组成基准，再在实际物性框架中重现实验条件。高压下不能未经逸度、活度及压力修正审查就把总压除以液相摩尔分数当作 Henry 常数。标定与独立温度或组成留出分开，验证结论只覆盖实际检验的范围。

依据：[物性与参数回归](textbook-properties-and-boundaries.md)，[吸收与传质](textbook-solids-and-mass-transfer.md)。

<a id="m02"></a>
## M02 严格塔规格与边界诊断

- **先查规格语义和自由度。** 设计规定逐项核对目标组分、产品流、相态、质量或摩尔基准，以及独立操纵量。指向错误产品或互不相容的规格，不能靠更多迭代解决。
- **操纵量触界先做物理诊断。** 检查物性、物料衡算、响应是否变平及规格是否可行，再以合理采出量和回流范围做原生塔扫描。不能把扩大上下限或放宽容差当成默认修复。扫描得到可行初值后恢复正式设计规定并独立复算。
- **诊断扫描成对处理 Design Spec 与 Vary。** 临时关闭规格时同步处理其操纵变量，恢复时核对二者及自由度。扫描的停止条件仅用于定位初值，不能充当最终验收标准；避免在塔本身的数值分辨能力以下反复细分。

依据：[精馏与规格](textbook-distillation-and-towers.md)，[收敛与分离诚信](convergence-separation-and-energy-integrity.md)。

<a id="m08"></a>
## M04 / M08 压力闭合、断流与循环

- **画面连接、物理闭合和数值收敛分别核验。** 循环存在净压损时须有实际压力来源；混合器不能充当升压设备。多段压缩应结合级间冷却、相态和压比核验，不能仅把目标出口压力分段填入。
- **断开或接回流股后重新分析收敛拓扑。** 原有手动撕裂和收敛对象可能变得多余、跨越子系统或引用失效对象。先区分拓扑分析阶段失败与迭代失败，再按当前闭环重选撕裂，不能沿用旧循环设置盲目调参。
- **切口成为边界时补齐真实输入。** 断流后独立进料需要完整状态、流量和组成；旧结果或循环猜值只能作为明确的初始化依据，不能自动变为已验证边界。接回后重新审查压力、热量及组分闭合。
- **用户禁用状态是修复边界。** 仅核对禁用标记及其对活动流程的接口影响；不得为消除历史错误而重新启用或深入修改被禁止的设备。不同文件版本间也要重新确认禁用状态。

依据：[压力网络](textbook-fluid-transport.md)，[循环与数值方法](textbook-numerics-economics-and-custom-models.md)。

## M09 最新文件、COM 与运行身份

- **用户另存后重新取得基准。** 核对文件时间、哈希、运行类别、实际设备、流股和反应集。仅物性计算文件不能作为完整流程修复或复算的证据；将其中物性用于完整流程时，明确两个来源及迁移范围，保留用户原文件。
- **先确认对象语义，再写入。** 二元参数树可能是多维集合，递归遍历名称可能混淆组分对。按实际集合维度与坐标定位，并分别核验数值字段和来源选择字段。写入后回读、保存、重开，不能由 setter 成功推断来源绑定成功。
- **原生输入修改先证明格式。** 优先使用已核验的 COM 接口；必要的文本修改以同版本同类对象的原生导出为参照，限定记录边界，保留编码、单位、续行及图形区。不得把数值字段和来源选择字段互换。工作副本导入后出现进程或 RPC 故障时，停止重复猜写，先检查格式与接口，不能直接归因于许可。
- **新运行必须有新证据。** Run2 返回或旧状态正常不证明引擎执行了本次改动。按任务需要重新初始化，记录实际工作目录、运行身份、最新历史、输入完整性、设备状态和独立衡算；原生归档可能在解包目录生成历史。退出前保存对应证据。
- **编辑前先读成普通快照。** 输入变更可能使旧输出节点失效；将已收敛状态读为普通数据后再用于初始化，避免持有失效 COM 节点。快照需标明来源，不能替代改动后的新结果。
- **参数修复不授权重排流程图。** 以用户最新排布为基准，分别核对设备和流股的图形记录；仅比较设备位置不足以证明连线布局被保留。保留默认标签、真实端口与用户禁用状态，不用重新生成图形掩盖参数修改。
- **交付验收分层。** 文件可打开、参数可溯源、流程可复算、衡算通过、设备能力适用和压缩包完整是不同结论。逐项提供相应证据与未验证范围。公开技能只收方法；新增内容、Git 暂存区和最终压缩包都要审查保密边界，改名或编码不能绕过限制。

依据：[输入完整与交付](aspen-input-completeness-and-delivery-lessons.md)，[运行核验](run-verification-and-reconcile.md)，[COM 与变量排障](variables-and-troubleshooting.md)。
