# 公用工程蒸汽生产装置（反应废热 → 熔盐中间载热 → 38 bar 饱和蒸汽）

> **层级**：第二原则支撑（案例与已验证工程，只作学习参考），服从 `SKILL.md` §1 两级原则。
> **案例来源**：用户提供的 `4.全流程最终版.bkp`（文档头 `MM "37.0"`，DATETIME 2025-08-10；PFD 上有文字标注“公用工程蒸汽生产”，图框 x=-28.0 / y=-29.9，位于“DMS合成及精制工段”图框内）。
> **复核方式**：2026-09-22 在本机 Aspen Plus V14（OLE 服务 40.0）用 COM 打开临时副本 → `InitFromFile2` → `Run2` 重跑（9~10 s，61 个模块 `BLKSTAT=0`、相关流股 `PER_ERROR=0`）→ 逐节点读取 In/Output。
> **数值纪律**：下表所有数值都是**该案例的工况值**，只用来说明“原理如何落地”。新任务必须回到第一原则重新推导（热源、蒸汽等级、循环倍率、盐种与流量都要有出处），**禁止照搬**。

## 0. 结论速览

**一句话**：DMS 合成反应器（RPlug `R0201`，360 ℃ 等温、放热 ≈840 kW）的反应热，经**硝酸熔盐中间回路**送到换热器 `E0208`，把锅炉给水变成 **38 bar(a) / 247 ℃ 饱和蒸汽 1 081 kg/h**。

装置由 **用户确认的 6 个模块 + 1 个计算器** 组成，两条回路在 `E0208` 上传热耦合、**没有物料耦合**：

| 位号 | 类型 | 在本装置中的角色 |
|---|---|---|
| `M0203` | Mixer | 熔盐补加 `0233` + 循环盐 `0237` → `0234` |
| `E0207` | Heater（带热流股端口） | 吸收反应器热流股 `S1`，把盐 `0234` 由 260 ℃ 加热到 334.66 ℃ |
| `E0208` | HeatX（Shortcut / DESIGN） | 唯一耦合点：热侧盐 `0235` 放热至 260 ℃，冷侧水 `0240` 受热汽化 |
| `M0204` | Mixer | 锅炉给水 `0239` + 汽包返液 `0243` → `0240`（实现循环倍率） |
| `T0206` | Flash2（`V-DRUM1` 汽包） | 247 ℃、`DUTY=0` 闪蒸 → 蒸汽 `0242` + 返液 `0243` |
| `M0205` | FSplit | 盐 `0236` 分流：0.9 循环、0.1 排污 `0238` |
| `C-2` | Calculator | 强制 `KNO3IN=KNO3OUT`、`NANO3IN=NANO3OUT`，即“盐补加 = 盐排污” |

> ⚠️ **典型错误**：不要把 `T0201`/`T0202`（甲醇汽化器，用 `HS`、`SALT` 公用工程，是**耗汽**设备）当成蒸汽生产装置；本装置的蒸汽发生单元是 `M0204`+`E0208`+`T0206`，热源侧是 `M0203`+`E0207`+`M0205`。

## 4. 可复用的 7 条建模手法

1. **用热流股把反应热“搬”到产汽装置**：RPlug/RCSTR 输出 Q 型热流股（`S1`）→ 接到 Heater 的热端口。此时 Heater **只给 `PRES`**，负荷由热流股决定；若再给 `TEMP` 或 `DUTY` 就是过规定。
2. **中间载热回路 = Mixer + Heater + HeatX + FSplit**：不用换热器组模型，用一条“载热流股回路”表达，物理量（流量、温升、温差）全部可见、可校核。
3. **产汽量用 Mixer 造循环倍率**：给水 `0239` 与汽包返液 `0243` 在 `M0204` 混合 → 循环倍率 N = 1500/1081.33 = **1.387**。
4. **HeatX 用 `CALC-TYPE=DESIGN` + `T-HOT`**：把“热侧出口温度”当设计规定（这里 = 盐回冷端 260 ℃），Shortcut 直接反算出 duty / LMTD / UA / 面积——这是“已知工艺要求、反算换热面积”的最快路径。要做正式选型再切 Detailed/EDR。
5. **汽包用 Flash2 + `TEMP` + `DUTY=0`**：给定汽包温度与绝热条件，由 VLE **反算压力**（等价于“给定饱和温度求饱和压力”）。本案例给 247 ℃，算得 38.03 bar。
6. **Calculator 闭合回路组分衡算**：`KNO3IN=KNO3OUT`、`NANO3IN=NANO3OUT`，让补加自动跟随排污，避免手改数字（参见 `references/calculator-flowsheeting-options.md`）。
7. **两条回路放同一个收敛块**：彼此只有热耦合、无物料耦合时，`$OLVER04` 一次撕裂 `0234`+`0240` 最简洁；撕裂流初值可用上一轮收敛结果做种子（参见 `references/run-verification-and-reconcile.md`）。

## 5. 从零搭建的步骤（原理驱动）

1. **热源核算**：先由反应动力学/热效应算出可回收热 `Q` 与温位（本案例 360 ℃ 等温、840 kW）。判据：热源温度必须显著高于目标蒸汽饱和温度。
2. **定蒸汽等级**：由用户/公用工程等级定压力 → 定汽包温度（本案例 38 bar ↔ ≈247 ℃）。
3. **定循环倍率 N**：由水循环方式（自然循环/强制循环）、含汽率与水力条件定；`N = 循环水/产汽量`。**本案例 N=1.39 偏小**，工程上常见取值更高，须按水力校核（不要凭本案例取值）。
4. **定载热介质流量与温升**：`Q = m·cp·ΔT`，`cp` 必须取自所选熔盐/导热油的物性数据。本案例隐含 `cp ≈ 1.13 kJ/(kg·K)`（36000 kg/h、ΔT = 74.66 K、840 kW），与常见硝酸盐文献值有差距 → **采用前必须核对所选盐的物性**。
5. **算换热面积**：`A = Q/(U·Δtm)`，并设最小接近温差约束（本案例热端接近温差 13.05 ℃）。U 要有出处（本案例由 `U-OPTION=PHASE` + 面积反推得 ≈849 W/(m²·K)）。
6. **建网**：Mixer/FSplit 造回路 → Heater 接热流股 → HeatX 定耦合 → Flash2 当汽包 → Calculator 闭合衡算。
7. **给初值并收敛**：撕裂流用收敛值做初值，WEGSTEIN/BROYDEN 起步，必要时收紧容差。

## 7. 本案例的不足与需复核项（准备照它建模前必须知道）

1. **水物性偏差 6.3 %**：水回路用 `PENG-ROB + FREE-WATER=STEAM-TA`，模型隐含 `hfg=1793.1 kJ/kg`（IF97 1729.0）、液相显热 1003.9 kJ/kg（IF97 901.9）。→ 绝对负荷/产汽量偏保守约 6 %；正式设计应改用与水蒸气表一致的水物性（NBS/NAS 或 IAPWS 系）复核，或按蒸汽表焓差反算产汽量。
2. **没有排污**：`0242` 产汽量（1 081.33 kg/h）= `0239` 给水量，`0243` 全部循环，模型排污水量为 0 → 炉水含盐量会无限浓缩。工程上必须给出连续排污率（由给水水质与炉水允许浓度定，属第一原则取值，不能沿用本案例的 0）。
3. **两条回路都没有泵、也没有压降**：熔盐回路与水回路内无 Pump，`E0208` 两侧 `DP-OPTION=CONSTANT` 且 Δp=0，压力完全由入口流股给定。真实装置有盐循环泵、给水泵与阻力降；按 `SKILL.md` §7.1 的要求，凡影响压力的单元都应给出有依据的负值压降。
4. **盐冷端 260 ℃ 裕量小**：硝酸盐混合物凝固点通常在 220~240 ℃ 量级（须按所选盐的实测凝固点核对），260 ℃ 的防凝裕量偏紧。
5. **“补加 = 排污”是建模简化**：`C-2` 强制 `0233` 与 `0238` 逐组分相等，导致 10 % 循环量的补加/排污——真实熔盐回路补加量很小，这里是让盐回路“自洽闭合”的技巧，不是真实换盐率。
6. **物性混用**：`E0207` 用 `UNIQUAC` 描述熔盐、`E0208` 两侧分别 `UNIQUAC`（热侧）/`PENG-ROB`（冷侧）、`T0206` 用 `PENG-ROB`。用活度系数模型（UNIQUAC）描述熔盐本身缺乏依据，建议改用所选熔盐的实际物性数据（密度、比热、导热、凝固点）或以载热流股规格处理。
7. **产出的蒸汽没有接回装置用汽点**：装置内加热/再沸全用 `UTILITY` 对象（`HS` 310 ℃、`MS` 247 ℃、`LS` 150 ℃、`SALT` 395→370 ℃、`CWS`、`RWS`、`CACL2`、`AIR`、`ELE`）。其中 **`MS`（247 ℃）已定义但没有任何模块使用（`UTILITY-ID=MS` 出现 0 次）**，而 `0242` 的温位正好等于 `MS`。→ 图形上表达“自产 MS 级蒸汽”，但模型里蒸汽作为产品排出、未进入蒸汽管网；如需做全厂蒸汽平衡，必须把 `0242` 按等级接入用汽模块。

**自建过程中确认的三个 `.inp` 硬约束（手写输入时必踩）**：

1. **块级 `PROPERTIES <方法>` 覆盖前，必须先在全局 `PROPERTIES` 段登记该方法**，否则 `InitFromFile2` 直接报 **2041 无法打开**：
   ```
   PROPERTIES IDEAL
       PROPERTIES PENG-ROB
       PROPERTIES STEAMNBS
   ...
   BLOCK T0201 FLASH2
       PARAM PRES=25. DUTY=0.
       PROPERTIES STEAMNBS
   ```
2. **非默认数据银行的组分（KNO3/NaNO3 等）必须显式写 `DATABANKS`/`PROP-SOURCES` 段**，否则同样 2041。
3. **循环收敛**：手写 `.inp` 中撕裂流不要写完整 `STREAM` 规格（与迭代冲突），但给它 T/P/流量**初值**能显著改善收敛；本案例给返液 `WREC` 初值后，盐回路质量平衡由 ~1 % 残差变为精确闭合。注意**初值温度必须落在液相区**：224 ℃（高于 25 bar 饱和温度 0.01 ℃）会触发首轮 `P0202` 的 "FEED HAS 100.00 % VAPOR" error，改 223 ℃ 后 `.his` 归零 error。大循环比回路建议 `WEGSTEIN MAXIT` 给到 200~300（本案例 MAXIT=1000 + `PARAM TOL=1.E-5`，第 547 次迭代收敛）。

**关于 `BALMAS.1`（回路质量衡算精度告警）——已消除，方法可复用**：默认收敛容差下，大循环比回路会报
`WARNING/ERROR WHILE IN SEQUENCE MONITOR (BALMAS.1)  STREAMS CROSSING THE LOOP ... NOT IN MASS BALANCE`（相对差 ~3.5E-04），
Aspen 提示语本身即写 "IMBALANCE MAY BE DUE TO A LARGE RECYCLE FLOW, AND A RELATIVELY LOOSE TEAR STREAM TOLERANCE"。
**根因是撕裂流容差偏松，不是设计上的物料不平衡**。已验证的消除办法（写入 `CONV-OPTIONS`）：
```
CONV-OPTIONS
    PARAM TEAR-VAR=NO
    WEGSTEIN MAXIT=1000
    PARAM TOL=1.E-5
```
收紧后 `$OLVER01` 第 547 次迭代收敛，`.his` 的 error/warning 计数均为 0。
**关键字实测**：`PARAM TOL=` 有效；`PARAM ERRTOL=` 与 `PARAM MAXIT=... TOL=...` 会直接 **2041 无法打开**。
（辅助手段：给撕裂流写 T/P/流量**初值**并保证初值落在液相区，可改善收敛并消掉首轮泵报错。）
