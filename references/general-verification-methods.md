# 通用基准验证方法论（跨版本方法）

> **文档定位：工具与机制层（中性）**，服从 `SKILL.md` §1 的两级原则。
> 本文方法**跨版本通用**；涉及具体节点名、单位或 API 处均以本机安装版本为准，不把任何特定版本结论当通用事实。
> 目标：把"看着对不对"升级为"**用独立物理基准证明对不对**"，支撑 SKILL.md §7.1 的全局验收与"不臆想"规则。

## 1. 标定方法（怀疑单位/数值口径时先用，不靠猜）

任何"输出与输入无关的诡异结果"或"单位不确定"场景，先用独立方法标定：
1. **物理闭环测试**：写入你认为正确的值，看输出是否物理合理（例：给加热器一个温度规格，若输出温度与规格一致且热负荷方向正确 → 该节点单位与理解一致；若出现 −193°C 这类非物理值 → 单位理解错了）。
2. **已知物系对照**：用性质已知的简单物系（如纯水，Cp≈4.186 kJ/(kg·K)）算理论值，与软件输出对比（功率/焓/温度变化），可标定热/功类单位。
3. **独立基准文件对照**：用官方示例或已人工核验的文件作基准，比较同一物理量在不同单位制/显示下的数值关系。

通用原则：**先确认文档单位制**（`IN-UNITS`/全局设置），读每个带量纲节点时同时读回单位字符串；不默认任何版本的单位结论。

## 2. 交叉验证金标准（"显示异常" vs "真错误"）

流程跑通但温度/热负荷"看着不对"时，不要凭直觉判错，用 4 个**互相独立的物理基准**交叉验证：

| 基准 | 做法示例 |
|---|---|
| 总物料衡算 | 每块 Σ进 = Σ出；组分衡算（有反应按元素衡算） |
| 相平衡基准 | 出口温度 vs 该组成/压力下的泡点、露点；结晶母液浓度 vs 溶解度表 |
| 焓/能平衡 | 等焓块进出口焓流 Σ(H·m) 守恒；能量守恒 Q + Σ(nH)进 = Σ(nH)出 |
| 热负荷 vs 理论 | 冷凝/再沸/换热负荷 vs 潜热/显热手算（Q = m·Cp·ΔT 或 Q = n·ΔH） |

判别结论：
- 「显示异常」但「物理基准吻合」→ 单位/显示/回显问题，不是模拟错误；
- 物理基准也不吻合 → 才是真正的模拟错误，回到模型找原因。

> 用基准"证伪/证实"而不是用感觉判断——这是"不臆想"的落地方式。

## 3. 焓污染判别（哪些数据可信、哪些不可信）

概念（通用）：某些建模结构——典型如 Chemistry 盐平衡 + 固体组分共存——可能把部分流股的摩尔焓算成**非物理值**，并连锁污染：① 由等焓反解温度的块（如绝热混合器）出口温度出现非物理根；② 下游换热/结晶块热负荷失真。**物料平衡与塔负荷通常不受影响。**

判别清单（通用操作化）：
- ✅ 通常可信：各流股物料衡算与组成、精馏塔冷凝/再沸负荷（可与潜热理论对照）、固体产量、分流器分流比、收敛器状态。
- ❌ 通常不可信：被污染流股的摩尔焓/质量焓、由等焓方程反解的混合温度、下游被连锁污染块的热负荷。
- 🔧 替代口径：热负荷用显热/潜热手算——`Q ≈ m·Cp·ΔT`；相变 `Q ≈ n·ΔH`（注意 kW / kJ/h / kcal/h 之间差 3600 或 4.1868，换算后必须量纲自检）。

> 具体哪些块在本机版本上会触发焓污染、污染哪些节点——用 §2 的基准验证实测确认，**不要照搬他人结论**。

## 4. 循环（撕裂流）收敛判定

带循环/回流的流程，判定"真正闭环"需三条件**同时**满足：
1. **好初值**：撕裂流按收敛温度/压力下的平衡态估算（如饱和母液、泡点组成）——初值差是循环不收敛最常见原因；
2. **守恒精确**：汇合/分流点物料精确守恒（Σ进 = Σ出），分流比与设定一致；
3. **收敛判据**：撕裂流收敛值与初值偏差小于设定阈值（阈值按任务说明，如 <0.1%）。

> 收敛器状态以本机版本的收敛结果节点/报告为准；不要只看"运行没报错"。

## 5. 运行与诊断通用规则

- **块是否真正执行**：以块的结果状态为准（Aspen 中常见为块输出状态：0=正常收敛、空/None=被跳过未执行、1=有告警但出结果）。**不要用 Design-Spec 的收敛误差百分比判断块失败**——那是设计规定的收敛误差，与块是否执行无关。
- **引擎"秒退"**：Run2 后几乎立即结束、输出子树未生成、无错误报告 → 是**输入不完整/非法**（某块缺输入、某压力为 0 等），不是"不收敛"——不收敛时输出树通常仍会生成。逐块查输入完整性。
- **输入完整性诊断**：优先用本机版本提供的完整性检查手段（如输入完整性 API 或导出报告中的缺失项）；当前版本没有对应 API 时，用"最小闭环 + 基准对照"定位缺失。
- **结果读取时机**：运行后需要的结果尽量在 Run2 后同一会话内读取/导出；保存后重开再读，组件级结果可能取不到（以本机版本行为为准）。

## 6. COM 自动化卫生（走 COM 时通用）

- 初始化后关闭弹窗（如 `SuppressDialogs`），防止 GUI 弹窗挂死脚本；
- `Quit()` 放 `finally`，并清理残留的 Aspen 进程（残留进程会污染下一次测试，表现为"假报错"）；
- 多次独立运行用强制新实例；同一实例不要二次初始化；
- COM 对象为 STA 单线程模型：所有调用必须在创建对象的同一线程；
- 早绑定缓存损坏（报 `CLSIDToClassMap` 一类错误）→ 删除 `%TEMP%\gen_py` 目录重建；
- 枚举/集合类操作避免缓存中间集合对象，优先链式调用（以本机绑定模式实测为准）；
- 多版本并存时：用带版本号的 ProgID 显式锁定目标版本，并用注册表枚举 `Apwn.Document.*` 探测本机已注册版本；COM 服务器位宽须与 Python 解释器一致。
