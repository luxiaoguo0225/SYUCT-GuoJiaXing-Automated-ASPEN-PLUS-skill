# PDO 双塔热集成、反应余热产汽与交付经验

来源：2026-09-27 至 2026-10-01 的用户 PDO 案例修复、节能改造和排版任务；Aspen Plus V14 本机实测。以下数值是案例证据，不能作为其他体系的默认输入。排版经验见 [pfd-layout-preservation-and-review.md](pfd-layout-preservation-and-review.md)。

## 1. 任务范围与结论边界

- 用户最初要求修改不合理工艺，随后要求两座塔节能、反应器余热产蒸汽。未指定塔时，应按可用热负荷、温差、压力及产品约束选择，并记录选择依据。
- 局部修复将 C-DEH 的馏出量从 38 调为 8 kmol/h、C-ACRREC 从 2 调为 1.5 kmol/h。这是该案例的修复结果，不能泛化成塔规格。
- R-OX、R-HYD、R-HG 的动力学输入保持不变；保留原动力学不等于重新验证其化学可靠性。核对导出反应语句及活化能等节点的 UnitString，不能只对数值。
- 双塔与产汽子系统完成稳态及冷启动验证。原 C-QUENCH 顶部约 −96.5 ℃ 的深冷问题未完成工业合理性修复，假想组分 HPA/DIM 的物性及原动力学适用性也没有获得新的验证。
- 因此不能把本次成果说成“全部工业设计已合理化”或“完成设备设计”。数值收敛、工程合理性、图面验收是不同的结论。

## 2. 先做热量品位与压力预算

列出热源/热汇的 T、P、相态、负荷、可用最低/最高温度、最小接近温差，以及产品约束。高品位热优先匹配较高温度热汇；低品位热用于较低温度进料或给水预热。检查全程温差及相变区，不能仅比较两个入口温度。

本例选择 C-HEAVY 顶部冷凝热供 C-DEACR 外再沸器：不是把两个塔的热负荷数字相减，而是建立物料连接的 HeatX、外冷凝及再沸回路。保留负荷不匹配时的辅助加热/冷却。

每段压力需满足流向、压降、相态和返回塔的压力。真空回路不能套普通正压服务的 0.2 bar 压降；极小压降也须说明压力余量及后续设备评级要求。真实回流/循环泵的压力提升应按回路预算计算，不能为了隐藏错误的压力剖面随意添加“补偿泵”。

## 3. 拆塔必须同时重映射理论级和流股

采用模式前先读 [column-splitting-and-heat-integration.md](column-splitting-and-heat-integration.md)。本例：

- C-HEAVY 原 100 级含冷凝器，外置冷凝器后保留 99 级，原第 50 级进料改第 49 级；`CONDENSER=NONE`，仍保留内部釜式再沸器。
- C-DEACR 原 6 级含釜式再沸器，外置后保留 5 级，第 3 级进料保留；`CONDENSER=TOTAL`、`REBOILER=NONE`。
- 外置相分离器与被移出的平衡级一一对应，不重复增加理论级。按原塔级定义逐项重映射所有进料、侧线、返回及规格，不能机械地将所有级号加减 1。

已验证连接：

```text
C-HEAVY 顶 H-VAP → HX-HDA → H-HX → H-COND → H-LIQ → H-SPLIT
  产品 HEAVY-TO；返液 H-R0 → H-RP → H-REF → C-HEAVY
C-DEACR 底 DA-BOT → DA-CP → DA-P → HX-HDA → DA-HX → DA-FL
  气相 DA-V → C-DEACR 底；液相 DEACR-B → 下游
```

逐步引入循环：先原塔收敛，再拆塔，再添加换热，最后水汽循环。蒸气返塔初值要处于蒸气区、液体泵入口初值要处于液相区；撕裂流初值不能变成与收敛器争夺自由度的完整固定进料规格。`Reconcile()` 只是辅助，保存后重开才可验证初始化是否保留。

## 4. 余热产汽的连接和自由度

本例 OX-R1/OX-R2 为约 360 ℃ 等温放热反应器。QOX1/QOX2 接 WHB1/WHB2 给水 Heater；Heater 只给压力，由输入热流确定热量，不再同时指定 TEMP 或 DUTY。检查 Aspen 热流方向和符号，不手工把反应器负号复制成水侧负热量。

```text
BFW(7100 kg/h,25 ℃,1 bar) → BFW-P(26 bar) → HX-BFW
 → BFW-H → BFW-HG2 → BFW-H2 → BFW-MIX(+WRECP) → WBF
 → WHB1 → WB1 → WHB2 → WB2 → SD-25(25 bar,DUTY=0)
SD-25：WH-STEAM → 外部蒸汽母管
       WH-LIQ → W-SPLIT → WH-BLOW
                         WREC → W-CP(25.6 bar) → WRECP
```

- 循环水 WREC 本例设 24000 kg/h、蒸发分率约 22%；这是初步循环假设，未证明最优，正式设计须校核循环倍率、干涸、汽水分离及水质。
- 同时给出补水、排污、实际压降及泵功，不能只交付无排污、无泵的理想蒸汽回路。
- HG1 约 50 ℃ 的低品位热不能直接生成 25 bar、约 224 ℃ 饱和蒸汽。本例经 CW-HG/CW-HOT 和 HX-BFW 预热给水至约 30 ℃，回收约 39.11 kW，余量仍由冷却系统排出。冷却水假设为 165 t/h、20 ℃、3.5 bar。
- HG2 小热负荷经 BFW-HG2 回收约 1.277 kW。HY-R 为需热模块，不能虚构成废热源。
- 产汽送外部母管，尚未指定实际用汽再沸器；不能额外把产汽热值从已经减少的塔外供热中再次扣除。

## 5. HeatX 语法、物性和单位陷阱

### 已验证的 U 输入形式

```text
PARAM ... U-OPTION=CONSTANT ...
HEAT-TR-COEF U=0.0119422948
```

本例导出 U 单位为 cal/(s·cm²·K)，该值约等于 500 W/(m²·K)。直接手写 `PARAM U=500` 的试验触发 2041；不得把失败脚本当可运行模板。新增模块或语句以本机 GUI/COM 导出形式为依据，并做最小案例验证。

### 水汽物性

先在全局注册 STEAMNBS，再给水/蒸汽模块覆盖物性。水–水 HeatX 两侧都需覆盖，本例导出为 `PROPERTIES STEAMNBS / STEAMNBS`；只写一个方法时另一侧仍使用原物性并产生告警。纯水饱和温度、潜热与 IAPWS-IF97 独立比较，不把含生成焓的绝对焓直接当汽化潜热。

### 单位必须实测

- 报告中的 CAL/SEC 不能无条件乘 4.184。本例 WATT 指定值与导出报告反算得到 Aspen 使用 4.1868 J/cal；8735700 W 导出约 2086486.10 cal/s。
- 根据本机 UnitString、显式单位输入与导出报告校准。记录单位及换算系数，不把该系数无条件推广到所有版本/单位集。
- `HMX_FLOW`、`HMX_MASS` 根节点本例 Value 返回 1，为集合结构值，不能当真实焓。读取正确相态/子流/组分叶节点或导出 `.rep`。保存文件重开未运行时某些输出为 None，不能当 0。
- 能量闭合使用同一物性及基准的流量×焓差，明确 kg/h 与 kg/s 换算。泵功、电效率和机械效率按相应定义分别核对。

## 7. COM、冷启动和文件隔离

1. 输入原文件、工作副本、交付目录分开。每次冷启动复制到新的独立目录；不在交付目录对任何文件调用 COM 初始化。
2. 记录源文件大小与 SHA256。`Dispatch` 成功不能证明许可有效；`InitFromFile2` 才可能报许可错误。已有环境变量为空时 `setdefault` 无效，应显式处理空值；在创建 COM 前设置已验证的许可主机。
3. 本次显式 LSFORCEHOST=127.0.0.1 加新工作目录后打开成功；此前多份控制文件也曾挂起。根因未被独立确定，不能把所有挂起都诊断成许可、损坏 PFS 或 COM 死锁。127.0.0.1 仅适用于本机许可服务，不能覆盖有效的远程配置。
4. 设置超时及运行日志，保存许可诊断到文件后筛选；不把几万行监控输出直接倾倒到对话。不要因一次挂起重置许可服务。
5. `Quit()` 放在 finally。需要终止残留进程时，仅处理本次明确记录的 PID 及已核实的子进程；不按进程名结束用户或归属未知的 Aspen 实例。
6. 运行后立即导出报告/输入，记录模块状态、关键产品、相态、全流程及子回路衡算。关联本次启动时间与运行目录的 `.his`，避免读到邻近旧日志；在退出前归档。
7. SaveAs2 生成 BKP 在本次 V14 案例多次成功重开，其他历史工作流曾失败。保留推荐 Export(1) 路径，但对任一保存路径都以独立目录的实际冷启动结果为准，不能仅以扩展名或 API 名称判定可用。
8. `Run2(False)`、输入完整、正常模块、日志无错、衡算/产品、独立冷启动须分别记录。不能用一项替代全部验收。

## 8. 失败试验与不应复用的做法

- C-QUENCH 修改 D/RR 的扫描未完成可靠工业修复；改成无冷凝/无再沸吸收塔并增加 40000 kmol/h 急冷水及预冷的试验也未形成认可方案。不要为收敛强迫非凝气全部冷凝或接受异常深冷，不要用巨量水忽略后续分离和加热代价。
- 初始化挂起不说明物理模型或图形损坏；先用独立工作目录、已知控制案例与许可环境诊断。
- 导出输入比较不能盲目删除前 5 行。只规范化已识别的时间戳等非模型头部，图形变化与工艺变化分别比较，并保留原始文件。
- 仅按扩展名和“说明书”名称判断文件类型不可靠。本次某 MD 实际含追加的 BKP 内容，追加原因未确定；交付检查应读文件头、尾、实际大小和内容，不猜测责任或复制混合文件到 skill。
- 用户已禁止 Computer Use 时不得调用 UI 工具；COM 校核和近似绘图不能冒充 Aspen 图面截图，也不能宣称 Control Panel 已目视检查。
